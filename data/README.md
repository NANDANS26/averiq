# Synthetic Data Documentation

This directory is used for synthetic training datasets generated by `make train`.

## Overview

Averiq uses a synthetic dataset for training and evaluating the recoverability
model. The dataset is generated deterministically from a random seed using
`ai/data/generator.py`.

## Generative Structure

### Latent Variables (not observable, never model features)

| Variable | Distribution | Description |
|----------|-------------|-------------|
| `creditworthiness_score` | Beta(2, 5) per customer | Latent payment reliability (0–1) |
| `failure_probability` | Derived from creditworthiness | Probability of payment failure |
| `intervention_response_probability` | Derived from failure_type + creditworthiness | P(recovery \| intervention) |

### Observable Features (model inputs at decision time)

| Feature | Type | Description |
|---------|------|-------------|
| `failure_code` | Categorical | Razorpay error code |
| `error_code` | Categorical | Gateway error code |
| `payment_method` | Categorical | card, upi, netbanking, wallet, emi |
| `exposure_tier` | Ordinal (HIGH/MEDIUM/LOW) | Derived from payment amount |
| `payment_attempt_count` | Integer | Number of prior attempts |
| `customer_success_rate` | Float (0–1) | Historical payment success ratio |
| `time_since_failure_seconds` | Float | From `decision_timestamp - failed_at` |
| `subscription_status` | Categorical | active, pending, halted, None |
| `hour_of_day` | Integer (0–23) | Hour of failure (UTC) |
| `day_of_week` | Integer (0–6) | Day of failure (0=Monday) |

### Target Label

`recovery_outcome = Bernoulli(intervention_response_probability)`

**Generated AFTER features via a separate, independent random draw.**
No feature column encodes or is derived from `recovery_outcome`.

## Label Leakage Prevention

The target label is generated after all features are fixed, using a separate
RNG call. The generative model ensures:

1. Features are derived from latent variables + random noise
2. `recovery_outcome` is drawn independently from `intervention_response_probability`
3. `intervention_response_probability` is a function of `failure_category` and
   `creditworthiness` — NOT a function of any feature column
4. No feature column can be used to perfectly predict the label

**LLM-derived `failure_category` (from `DiagnosisOutput`) is NOT a model feature.**
The model uses the deterministic `failure_code` from gateway data.

## Temporal Structure

Cases are assigned timestamps spread over 365 days before 2024-01-01 UTC.
The temporal split in `ai/training/feature_extraction.py` uses:

- **Training**: `created_at < 2023-09-01`
- **Validation**: `2023-09-01 ≤ created_at < 2023-11-01`
- **Test**: `created_at ≥ 2023-11-01`

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `DATASET_SIZE` | 50000 | Cases to generate (valid: 100–250000) |
| `RANDOM_SEED` | 42 | Random seed for reproducibility |

Same seed + same count = identical dataset on every run (Property 12, EVAL-006).

## Usage

```bash
# Generate and train (default 50,000 cases)
make train

# Smoke test with smaller dataset
DATASET_SIZE=500 make train

# Evaluate quality
make evaluate

# Simulation metrics
make simulate
```

## Base Recovery Rates by Failure Category

These rates represent the latent `intervention_response_probability` baseline.
They are documented here as part of the generative model (EVAL-007):

| Failure Category | Base Recovery Rate | Rationale |
|-----------------|-------------------|-----------|
| INSUFFICIENT_FUNDS | 15% | Structural — customer may not be able to pay |
| CARD_DECLINED | 35% | Moderate — often transient bank decisions |
| EXPIRED_CARD | 55% | High — customer can update card |
| AUTHENTICATION_FAILURE | 60% | High — abandoned auth can be retried |
| TECHNICAL_FAILURE | 70% | High — transient, self-resolving |
| NETWORK_TIMEOUT | 65% | High — transient network issue |
| FRAUD_SUSPECTED | 10% | Very low — requires manual review |
| LIMIT_EXCEEDED | 40% | Moderate — limit may reset |
| UNKNOWN | 25% | Below average — uncertain root cause |

These are NOT hardcoded targets for `make evaluate` — they are generative
assumptions that produce realistic training data. Evaluation metrics are
computed empirically from model predictions on held-out test data.
